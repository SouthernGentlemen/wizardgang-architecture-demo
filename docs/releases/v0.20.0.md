# WizardGang Architecture Demo v0.20.0

**Product:** WizardGang Architecture Demo

**Version:** v0.20.0

**Release date:** 2026-09-14

**Commit:** the commit this tag names — `git rev-list -n1 v0.20.0`

## Scope

Release the completed demonstration activation, accessibility analysis, interactive edge-compute, evidence-presentation, site-assurance, and API-surface improvements after DEMO-248 through DEMO-253 were merged into `main` in dependency order.

## Included changes

- DEMO-248: activate consolidated demonstrations on demand through registered, offline-gated presentation fragments and clean scoped runtime teardown.
- DEMO-249: present accessibility failures as inert escaped fixtures beside one live accessible workflow and explicit automated/manual verification limits.
- DEMO-250: make the Edge, Workers, and Durable Objects demonstrations directly interactive.
- DEMO-251: clarify executable demonstration evidence, states, actions, and progressive supporting detail.
- DEMO-252: polish the task-oriented site and assurance presentation hierarchy without changing its route architecture.
- DEMO-253: clarify public API boundaries, retain the visitor-scoped R2 workspace, retire duplicate R2 routes, and distinguish REST browser and authorized machine contracts.

## Validation

The release candidate passed the complete repository check with 548 tests across 94 test files, clean local migration application, the dependency audit with zero vulnerabilities, the Worker dry-run build, and `git diff --check`. The local Chromium audit passed 6 canonical public routes, 12 route/locale renders, 5 explicit state fixtures, 28 axe runs, 4 narrow-reflow samples, and 4 keyboard-smoke samples. The final merged `main` state also passed GitHub CI.

The automated accessibility result is limited to no automatically detectable violation observed in the bounded matrix. It does not establish WCAG conformance or certification.

## Deployment

Target: `demo.wizardgang.ai`. The tag-triggered Release workflow reproduces the annotated v0.20.0 state, publishes a release-bound assurance snapshot, deploys the exact tag, and verifies public version/commit identity and Worker health.

## Known limitations

- Intentionally inaccessible accessibility examples remain inert teaching fixtures; automated scanning and the documented manual matrix are bounded engineering evidence, not a conformance claim.
- Identity demonstrations still depend on provider configuration and expose only the behavior available in the configured production environment.
- `/admin` remains private and non-indexable, while `/offline` remains a public but non-indexable recovery surface outside normal navigation.
