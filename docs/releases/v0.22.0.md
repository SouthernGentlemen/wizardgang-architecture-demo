# WizardGang Architecture Demo v0.22.0

**Product:** WizardGang Architecture Demo

**Version:** v0.22.0

**Release date:** 2026-09-15

**Commit:** the commit this tag names — `git rev-list -n1 v0.22.0`

## Scope

Release the completed Demo Workbench after DEMO-264 through DEMO-271 were merged into `main` in dependency order.

## Included changes

- DEMO-264: define the Demo Workbench roadmap and reserve its ordered delivery sequence.
- DEMO-265: replace the repeated demo inventory with a tabbed, fragment-driven workbench that mounts one demonstration at a time.
- DEMO-266: standardize complete GitHub Actions job-log retrieval before CI diagnosis.
- DEMO-267: add the focused demonstration pane and bounded Guide, Request, and Evidence inspector modes.
- DEMO-268: keep REST operation-first and contain oversized implementation evidence behind deeper surfaces.
- DEMO-269: make CI failures reproducible through bounded diagnostic logs and artifacts.
- DEMO-270: harden keyboard, focus, history, locale/RTL, loading/error, and responsive workbench behavior.
- DEMO-271: enforce the accepted Demo Workbench contract with focused regression coverage.
- DEMO-272: set the release version, record release and rollback evidence, and retire the completed temporary implementation plan.

## Validation

The release candidate passed a clean dependency installation, the full repository check, clean local migration application, the real Chromium accessibility and interaction audit, the high-severity dependency audit, the Worker dry-run build, whitespace validation, and the CI-equivalent validation command. The final merged `main` state must also pass GitHub CI before the annotated release tag is created.

Pre-release browser acceptance covers all twelve stable Demo Workbench fragments, one mounted presentation at a time, D1 default selection, category and secondary-selector keyboard behavior, inspector operation, browser history, direct fragment loading, representative REST GET and PATCH operations, contained loading/error behavior, narrow reflow, and Arabic/RTL state preservation. Automated accessibility results are bounded engineering evidence; they do not establish WCAG conformance or certification.

## Deployment

Target: `demo.wizardgang.ai`. The tag-triggered Release workflow reproduces the annotated v0.22.0 state, publishes a release-bound assurance snapshot, deploys the exact tag, and verifies public version/commit identity and Worker health.

Post-deployment verification covers the homepage, `/demos`, representative workbench fragments, one-presentation mounting, representative REST GET and PATCH operations, `/assurance`, `/security`, the retired `/operations` 404, declared machine/API/protocol routes, English and Arabic locale navigation, narrow-layout containment, and deployed v0.22.0 identity.

## Known limitations

- Identity demonstrations depend on provider configuration and expose only the behavior available in the configured production environment.
- Automated accessibility and localization checks cover a bounded matrix and do not replace manual or assistive-technology review.
- `/admin` remains private and non-indexable, while `/offline` remains a public but non-indexable recovery surface outside normal navigation.
- Operational machine APIs remain public where declared even though the retired human `/operations` page returns the ordinary application 404.
