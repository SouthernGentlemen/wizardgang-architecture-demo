## Deployment

Target: `demo.wizardgang.ai`

The release workflow reproduces this annotated tag, publishes these notes, applies migration `0009_crawler_control.sql` with access disabled, deploys the exact tagged Worker source with its release identity, and verifies `/version` and `/health` against the tag commit.

After deployment, an authenticated operator can use the ChatGPT access card on `/dashboard` or the full control on `/admin#chatgpt-crawl` to enable search and user-requested fetching. The default remains disabled until that explicit action.

## Known limitations

- ChatGPT Search systems may take about 24 hours to observe a `robots.txt` change even though the Worker request gate changes immediately.
- User-agent matching expresses public-site crawler policy; it is not crawler identity authentication and does not protect private content.
- `GPTBot` is always blocked. This release does not opt demo content into foundation-model training.
- Visitor write laboratories require the managed session secret and enforce per-session quotas and 24-hour expiry.
- Branch-protection evidence is reported as unverifiable when GitHub does not expose it anonymously and no optional read token is configured.
- Real GitHub webhook delivery requires environment-owned repository webhook configuration and a matching managed secret.
- Identity examples are provider-neutral boundaries, not a configured external tenant.
- WCAG and ISO references are alignment demonstrations, not certification claims.
- Billing data is synthetic.
- R2 uploads are limited to 10 objects, 5 MiB per object, and 20 MiB total per visitor session.
