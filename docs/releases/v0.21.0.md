# WizardGang Architecture Demo v0.21.0

**Product:** WizardGang Architecture Demo

**Version:** v0.21.0

**Release date:** 2026-09-15

**Commit:** the commit this tag names — `git rev-list -n1 v0.21.0`

## Scope

Release the completed minimal public architecture-demo experience after DEMO-255 through DEMO-262 were merged into `main` in dependency order.

## Included changes

- DEMO-255: define the minimal public-demo contract and ordered MVP implementation sequence.
- DEMO-256: reduce the public shell to a demo-first homepage, focused navigation, and compact operational proof.
- DEMO-257: curate `/demos` around visitor-facing capabilities while preserving stable fragments and machine contracts.
- DEMO-258: reduce `/assurance` to four focused verification checks while preserving canonical records and reporting APIs.
- DEMO-259: retire the human `/operations` route while preserving operational APIs, collection, retention, logging, and protected controls.
- DEMO-260: enforce the completed MVP surface and preserved machine boundaries with consolidated acceptance coverage.
- DEMO-261: remove obsolete planning and transition documents after the MVP sequence completed.
- DEMO-262: refresh permanent documentation contracts and restore implementation plans as an explicitly scoped planning tool.

## Validation

The release candidate passed `npm run check`, clean local migration application, the high-severity dependency audit, the Worker dry-run build, and `git diff --check`. The final merged `main` state must also pass GitHub CI before the annotated release tag is created.

Automated accessibility results are bounded engineering evidence. They do not establish WCAG conformance or certification.

## Deployment

Target: `demo.wizardgang.ai`. The tag-triggered Release workflow reproduces the annotated v0.21.0 state, publishes a release-bound assurance snapshot, deploys the exact tag, and verifies public version/commit identity and Worker health.

## Known limitations

- Identity demonstrations depend on provider configuration and expose only the behavior available in the configured production environment.
- Automated accessibility and localization checks cover a bounded matrix and do not replace manual or assistive-technology review.
- `/admin` remains private and non-indexable, while `/offline` remains a public but non-indexable recovery surface outside normal navigation.
- Operational machine APIs remain public where declared even though the retired human `/operations` page returns the ordinary application 404.
