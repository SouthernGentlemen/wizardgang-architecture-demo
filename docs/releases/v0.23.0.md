# WizardGang Architecture Demo v0.23.0

**Product:** WizardGang Architecture Demo

**Version:** v0.23.0

**Release date:** 2026-09-16

**Commit:** the commit this tag names — `git rev-list -n1 v0.23.0`

## Scope

Release the completed Shell Consolidation after DEMO-273 through DEMO-280 were merged into `main` in dependency order.

## Included changes

- DEMO-273: define the Shell Consolidation plan and reserve its ordered delivery sequence.
- DEMO-274: remove the unreachable breadcrumb, secondary-navigation, related-navigation, and shell-navigation layers.
- DEMO-275: make primary navigation derive directly from authoritative route declarations without a hardcoded allowlist.
- DEMO-276: consolidate the site header into one non-wrapping row and correct the theme control's accessible name.
- DEMO-277: complete the footer's security, provenance, version, and commit contract.
- DEMO-278: purge retired-surface stylesheet rules and add a check that prevents unreachable class-only rules from accumulating.
- DEMO-279: serve the content-hashed shared stylesheet through the cacheable asset route while keeping bounded critical CSS inline and demo CSS scoped to `/demos`.
- DEMO-280: enforce the accepted shell, navigation, footer, responsive, accessibility, provenance, and stylesheet contracts with focused regression coverage.
- DEMO-281: set the release version, record release and rollback evidence, preserve the permanent shell invariant, and retire the completed temporary implementation plan.

## Validation

The release candidate passed a clean dependency installation, the full repository check, clean local migration application, the high-severity dependency audit, the Worker dry-run build, whitespace validation, and the CI-equivalent validation command. The final merged `main` state must also pass GitHub CI before the annotated release tag is created.

Pre-release shell acceptance covers declaration-driven Demos and Assurance primary navigation, the footer security and provenance links, version and commit identity on every page, one Route source link per page, the absence of retired navigation layers, theme-control accessible naming, non-wrapping header behavior at 375px, 620px, 760px, and 1024px, cacheable content-hashed stylesheet delivery, and rejection of unreachable class-only stylesheet rules. Automated accessibility results are bounded engineering evidence; they do not establish WCAG conformance or certification.

## Deployment

Target: `demo.wizardgang.ai`. The tag-triggered Release workflow reproduces the annotated v0.23.0 state, publishes a release-bound assurance snapshot, deploys the exact tag, and verifies public version/commit identity and Worker health.

Post-deployment verification covers the homepage, `/demos`, `/assurance`, `/security`, the retired `/operations` 404, declared machine/API/protocol routes, English and Arabic locale navigation, 375px shell containment, the cacheable content-hashed stylesheet, exact v0.23.0 version/commit identity, and operational Worker health.

## Known limitations

- Identity demonstrations depend on provider configuration and expose only the behavior available in the configured production environment.
- Automated accessibility and localization checks cover a bounded matrix and do not replace manual or assistive-technology review.
- `/admin` remains private and non-indexable, while `/offline` remains a public but non-indexable recovery surface outside normal navigation.
- Operational machine APIs remain public where declared even though the retired human `/operations` page returns the ordinary application 404.
