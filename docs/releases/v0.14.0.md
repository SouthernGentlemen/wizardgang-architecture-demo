# WizardGang Architecture Demo v0.14.0

**Product:** WizardGang Architecture Demo

**Version:** v0.14.0

**Release date:** 2026-09-07

**Commit:** the commit this tag names — `git rev-list -n1 v0.14.0`

## Scope

Release the public-assurance, reporting, and route-consolidation baseline introduced by DEMO-117 through DEMO-187. The release replaces the 25 HTML paths and 92 total route entries published in v0.13.0 with eight HTML paths and 61 declarative routes, one canonical reporting contract, shared query and presentation layers, derived relationships, and explicit public/private provider boundaries.

The canonical HTML route inventory is:

- `/`
- `/platform`
- `/interfaces`
- `/assurance`
- `/security`
- `/operations`
- `/admin`
- `/offline`

Removed paths are unregistered and use the ordinary 404. This release provides no retired redirect, alias, proxy, dual endpoint, or client-side routing fallback.

## Included changes

- [DEMO-117–152] Publish the disclosure-safe ISO/IEC 27001, ISO/IEC 42001, and WCAG assurance baseline; add lifecycle, freshness, discovery, integrity, and synchronization validation; and establish canonical query and filter behavior.
- [DEMO-153–164] Consolidate reporting around authoritative sources and a public/private disclosure boundary; add protected GitHub and Cloudflare providers, retained reports, governance derivation, and shared availability and presentation behavior.
- [DEMO-165–173] Remove compatibility route families, introduce the generic declarative router, publish OpenAPI 3.1, and validate successful runtime reporting payloads against the canonical JSON Schema.
- [DEMO-174–178] Store relationship edges once, derive reverse graphs and counts, and unify structured and provider pagination behind one signed opaque cursor contract.
- [DEMO-179–186] Collapse the platform, interface, assurance, operations, laboratory, identity, and protocol pages into query-selected views on the eight canonical HTML pathnames.
- [DEMO-187] Complete the implementation audit: remove remaining duplicate endpoints and compatibility-only behavior, retain only the canonical reporting family, enforce private-source authorization, and delete unreachable code, contracts, fixtures, tests, styles, scripts, and configuration.
- [DEMO-188] Publish the complete merged baseline as v0.14.0 and align package and lockfile release identity.

The canonical reporting endpoints are `GET /api/reporting`, `GET /api/reporting/{collection}`, and `GET /api/reporting/{collection}/{recordId}`. Operations identity and health are exposed at `GET /api/operations/version` and `GET /api/operations/health`; logs and budget remain at their registered `/api/operations/*` paths.

## Known limitations

- Removed page, `/v1/assurance/**`, `/__api/**`, versioned OpenAPI and webhook, GraphQL console/schema, identity helper, MCP alias, and per-family reporting paths intentionally break callers with an ordinary 404; no migration redirect is provided.
- Public assurance data is a disclosure-safe projection, not the complete private operational, forensic, treatment, vulnerability-report, risk-acceptance, provider, or incident-investigation record.
- ISO/IEC 27001 and ISO/IEC 42001 records describe alignment posture only; certification is not claimed.
- WCAG records are criterion-level implementation and evidence observations, not a formal A, AA, or AAA conformance claim or certification.
- Protected GitHub inspection depends on correctly scoped deployment credentials and explicit source bindings. Anonymous visitors cannot enumerate a private source or receive its metadata or content.
- Repository evidence resolves only against the exact deployed commit identified by `DEPLOYED_SHA`; no moving-branch fallback is used when deployment identity is unavailable.
- Time-bound observation evidence is valid only through its recorded `validUntil`; stale observations fail validation rather than being silently treated as current.
- Published advisories remain distinct from incidents and may legitimately be empty. An empty advisory dataset does not claim that no vulnerabilities, reports, defects, or investigations have existed.
- Rolling back to v0.13.0 restores the former page and API contract as well as the application state; clients must account for that route-contract reversal.
