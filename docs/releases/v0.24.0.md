## Scope

Release the completed Assurance Assessment after DEMO-282 through DEMO-292 were merged into `main` in dependency order.

`/assurance` now gives every ISO/IEC 27001:2022 and ISO/IEC 42001:2023 clause and Annex A control and every WCAG 2.2 Level A, AA, and AAA success criterion a pass, partial, gap, or not-applicable status with a rationale, what is missing, the Markdown documentation that governs it, and its canonical evidence records. The canonical evidence records and every `evidence` relationship are unchanged. The release also stops exposing identity audit values in public responses and keeps internal localization placeholders out of rendered pages.

## Deployment

Target: `demo.wizardgang.ai`. The tag-triggered Release workflow reproduces the annotated v0.24.0 state, publishes a release-bound assurance snapshot, applies pending D1 migrations, deploys the exact tag, and verifies public version/commit identity and Worker health.

### Prerequisite: identity audit secret

DEMO-291 added the managed Worker secret `IDENTITY_AUDIT_HMAC_SECRET`. Set it on the production Worker before pushing the v0.24.0 tag, because the tag push deploys:

```bash
npx wrangler secret put IDENTITY_AUDIT_HMAC_SECRET
```

Generate a new value from a cryptographically secure random source with at least 32 random bytes, following `docs/governance/CRYPTOGRAPHY-SECRETS-KEY-MANAGEMENT.md` §7, and do not reuse `IDENTITY_SESSION_SECRET` or any other secret. The application treats a value shorter than 32 UTF-8 bytes as missing. Setting the secret while v0.23.0 is live does not change v0.23.0, which does not read it.

Without this secret, every identity provider reports itself unconfigured, so new sign-ins are unavailable, and token, authorization, and sign-out requests from visitors who are already signed in fail. The Release workflow's health check does not detect this, so it is verified separately below.

### Data changes

Migration 0013 runs during deployment. It removes unkeyed subject values from retained identity audit events and identity application logs, and it deletes existing visitor sandbox records. Existing identity sessions remain valid. Sandbox data that visitors created before the deployment is removed, and demo access tokens issued before it stop working. An authenticated visitor requests a new token to receive a fresh sandbox.

### Verification

Post-deployment verification covers:

- the homepage, `/security`, and the retired `/operations` 404;
- `/demos`, including the D1 Users table in English and Arabic without internal placeholder text;
- `/assurance` for each framework and representative deep links such as `/assurance#ISO27001-A.5.19`, `/assurance#ISO42001-A.9.4`, and `/assurance#WCAG-2.4.7`;

- exact v0.24.0 version/commit identity and operational Worker health.

## Known limitations

- No ISO/IEC 27001 or ISO/IEC 42001 requirement passes. Most are partial, and each names what is missing — commonly an operating record that has not happened yet, such as the access review AR-001, recovery test RT-001, incident exercise EX-001, awareness cycle AW-001 through AW-007, the competence and supplier reviews, or the first management review. No operating record was created or simulated to raise a status.
- Internal audit (clause 9.2) is a gap in both standards because no formal internal audit has been performed; the 2026-09-17 self-assessments are owner/operator reviews, not internal audits.
- `main` has no provider-enforced branch protection or rulesets, so ISO/IEC 27001 A.8.25 and A.8.32 remain partial.
- WCAG 2.2 criterion 1.4.10 Reflow is a gap. At 320 CSS pixels, the `/demos` D1 presentation overflows horizontally (about 334px of content in a 320px viewport), because its two table-tab controls keep 145px minimum widths.
- No screen reader or other assistive technology was used in the WCAG evaluation, so criteria whose result depends on that testing remain partial. Automated accessibility and localization checks cover a bounded matrix and do not replace manual or assistive-technology review.
- Every scheduled Assurance Monitor run since the workflow was added on 2026-09-03 has failed. Its live check receives HTTP 403 from `/security` on GitHub-hosted runners, while the same page returns 200 to ordinary requests. The monitor's repository-side assurance validation passes.
- The `claims` collection remains available through `/api/reporting` but no longer has a page consumer; retiring it requires its own controlled change.
- Identity demonstrations depend on provider configuration and expose only the behavior available in the configured production environment.
- `/admin` remains private and non-indexable, while `/offline` remains a public but non-indexable recovery surface outside normal navigation.
- Operational machine APIs remain public where declared even though the retired human `/operations` page returns the ordinary application 404.
