# WizardGang Architecture Demo v0.16.0

**Product:** WizardGang Architecture Demo

**Version:** v0.16.0

**Release date:** 2026-09-08

**Commit:** the commit this tag names — `git rev-list -n1 v0.16.0`

## Scope

Present the six-page Operations journey as an explanation, demonstration, result,
evidence, and source experience while preserving live runtime behavior and contracts.

## Included changes

- DEMO-201: guided Operations overview and runtime-to-evidence visual.
- DEMO-202: measured availability history and observation disclosure.
- DEMO-203: public-safe logging examples and preserved explorer filters.
- DEMO-204: cost-aware degradation simulator before provider telemetry.
- DEMO-205: shared reporting explanation with preserved evidence pagination and deep links.
- DEMO-206: curated documentation groups and deterministic sources.
- DEMO-207: journey acceptance regression and local keyboard/mobile verification.
- DEMO-208: update Vitest and Wrangler, override transitive Sharp to its patched 0.35.4 line, bound test concurrency to two workers, and prepare release metadata. This removes the dependency-audit blocker recorded during DEMO-207.

## Validation

The release PR and exact annotated tag must pass `npm ci`, `npm run check`,
`npm run validate:migrations`, `npm run security:dependencies`, and `npm run build`.
The PR also requires `git diff --check`. See `docs/OPERATIONS-ACCEPTANCE.md` for
local six-page acceptance evidence, including keyboard disclosure, empty states,
320px/390px/1280px layouts, and evidence drill-down.

## Deployment

Target: `demo.wizardgang.ai`. The tag-triggered Release workflow reproduces the
annotated v0.16.0 state, publishes a release-bound assurance snapshot, deploys the
exact tag, and verifies public version/commit identity and Worker health.
The GitHub Release notes will record observed deployment and live journey results.

## Known limitations

- Provider billing availability is independent of application health; unavailable billing is never estimated as real cost.
- Availability is measured observation history, not an SLA.
- Acceptance is not accessibility certification or an exhaustive cross-browser test.
- The Sharp override is retained until the upstream development toolchain declares a patched dependency itself.
