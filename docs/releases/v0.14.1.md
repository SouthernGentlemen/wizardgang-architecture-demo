# WizardGang Architecture Demo v0.14.1

**Product:** WizardGang Architecture Demo

**Release date:** 2026-09-07

**Commit:** the commit this tag names — `git rev-list -n1 v0.14.1`

## Scope

Correct the Cloudflare Worker startup failure in v0.14.0 without changing its reviewed route, reporting, disclosure, or data contracts. Reporting cursor fallback randomness is now generated lazily during request-time use instead of during module evaluation.

v0.14.0 passed tagged reproduction, published its GitHub Release, and applied production migration `0012_retire_cloudflare_usage_snapshots.sql`, but Cloudflare rejected Worker activation with error 10021 before the new Worker version became active. Its deployment verification therefore did not run. v0.14.1 is the forward correction; the published v0.14.0 tag is not moved or deleted.

## Known limitations

- The v0.14.0 production migration completed even though its Worker activation failed. It retires an unused snapshot table and is safe for the v0.13.0 Worker that remained active; v0.14.1 treats it as already applied.
- Deployed environments still require a stable `DEMO_SESSION_SECRET` for cursors to resume across Worker isolates. The lazy random fallback is for direct and local test helpers and is isolate-local by design.
- Removed page and API families intentionally return the ordinary 404 and have no compatibility route.
- Protected GitHub inspection depends on correctly scoped deployment credentials and explicit source bindings. Anonymous visitors cannot enumerate a private source or receive its metadata or content.
- Public assurance data remains a disclosure-safe projection and does not claim ISO/IEC or WCAG certification or formal conformance.
